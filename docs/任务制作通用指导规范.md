# 任务制作通用指导规范

> 版本：1.0（2026-08-10）
> 适用范围：KIBO 官网所有任务。自 `AGENTS.md` 0.4 起，所有任务统一采用**赛璐璐（cel-shaded）风格实时 3D 沉浸式游戏化任务体验**，不再制作 2.5D 任务。
> 定位：本规范是 `AGENTS.md` 原则 #7 与「3D 任务舞台准入条件」的跨任务落地细则；任务专属文档放 `docs/<任务名>/`，本规范为通用文档，不放入任何单一任务文件夹（见 `AGENTS.md` 第九节）。
> 证据来源：本规范全部条目均提炼自火星样板任务的讨论、开发与多轮三方 QA 记录，主要引用见各节末「来源」。

---

## 0. 如何使用本规范

1. 新任务启动时，先读本规范，再进入 `docs/<任务名>/` 的专属策划与设计。
2. 本规范定义**跨任务不变**的硬性基线（美术语言、准入条件、通用 UI 组件、验收流程）。任务专属的差异只在**内容、知识点、地图机制、POI 与教学闭环**上发挥。
3. 任何一条与本规范冲突的设计，须先在策划文档记录原因、证据、影响与替代方案，经用户确认后改代码并落决策变更记录（`AGENTS.md` 第二节规则）。
4. 通用 UI 组件（§4.6）的视觉与交互在**所有任务中必须保持一致**，不允许各任务自造一套皮肤、布局或图标语义。

## 1. 美术风格统一规范（cel-shaded）

所有任务的视觉语言必须统一为明亮、精致、卡通渲染（cel-shaded）。下面是验收级细则。

### 1.1 视觉基调
- 明亮、精致、卡通渲染；暗面统一冷灰、亮面暖调，整体不脏、不灰、不过曝。
- 每个任务定义自己的 palette（主色 / 重音 / 暗部），但**光影语言与赛璐珞语法全站一致**。

### 1.2 赛璐珞两阶 / 三阶光影
- 所有表面必须是**硬边明暗，无渐变模糊**；禁止用平滑 Lambert/Phong 渐变冒充卡通。
- 通过量化 ramp（2–3 阶）把光照切成硬边带；亮面、中间面、暗面之间有清晰边界。
- 暗面统一冷灰、亮面暖调，保证不同资产放到同一画面不打架。

### 1.3 描边规则（反向外壳描边）
- 采用反向外壳（inverted-hull）描边，屏幕空间恒定宽度：`clip.xy += nView.xy * thickness * clip.w`，保证**近处不肥、远处不消失**。
- 厚度按资产类别分级：
  - 车辆 / 机器人等结构复杂件：描边 **1.0–1.3**（稍细避免糊成一团）。
  - 基地 / 地标等远距离观看件：描边 **0.8–1.0**（稍粗保证剪影）。
- 所有不透明表面使用**统一的 cel 材质 + 共享 ramp**，保证与地形同一种光影语言（车体明暗与地形同源）。

### 1.4 菲涅尔轮廓光
- 掠射角量化成硬边冷白描边光（`uRimColor` / `uRimStrength`），强化卡通「边缘发光」。
- **亮背景下必须降 rim 强度**（如 `0.5 → 0.35`），并在地形远端加空气透视描边（fog outline），防止边缘「糊进天」。

### 1.5 剪影优先
- 任一角度 **3 秒以内必须能读出物体身份**（车、机器人、基地、岩塔、穹丘、沙丘）。
- 主表面必须通过面板线、层理、裂纹打破单调；**禁止纯色大面积光滑面**（车身、穹顶、沙丘等）。

### 1.6 结构可读
- 复杂机械用「大面分块 + 关节球 + 面板线」表达，禁止一片光滑几何体。
- 发光件用统一 emissive 通道（角色眼 / 胸盘、基地信标 / 舷窗、镜头、低电量告警），不靠后期泛光冒充体积光。

### 1.7 三视图基准与比例
- 每个主资产先出**正 / 侧 / 俯三视图**作为唯一建模依据，并附 `README-建模指导.md`（主美术明确优化细节）。
- 长 / 宽 / 高比例、部件相对位置、特征点与三视图误差 **≤10%**；色彩忠于 palette。

### 1.8 禁止项（验收红线）
- 未加工的纯色块、默认 `MeshBasicMaterial`、明显未完成的临时渐变冒充成品场景。
- 大面积光滑球体 / 盒体无细节、贴条代替块面、标志件过细不醒目。
- 用「漂亮插画 + 下一步按钮」包装成项目学习。

**来源**：`docs/火星任务/评审记录/3D资产主美术优化指南-2026-08-07.md`（§一、§八）、`docs/火星任务/评审记录/M3-赛璐珞描边管线-2026-08-06.md`（§1）、`AGENTS.md` 第五节素材规则。

## 2. 3D 资产与场景设计规则

### 2.1 资产生产流程
1. 先出三视图 + 建模指导（唯一依据）。
2. 程序化几何体 / 着色器材质 / 程序化贴图（Canvas 2D 或 GLSL 噪声）视为**正式素材**，不属于占位图，但仍须达到发布质量。
3. 主美术按三视图逐条勾选验收项（剪影 / 赛璐珞 / 结构可读 / 比例 / 色彩 / palette），迭代到「风格、比例、特征一致」为止。

### 2.2 场景分层（七层）
每个主场景至少拆分：**远景、后景、中景、前景、角色、反馈、UI**。不需要运动的元素不得为「分层」而无意义拆碎。

### 2.3 构图与相机
- 固定斜俯视，不允许自由旋转观光（学生注意力在任务，不在观光）。
- 桌面主舞台占宽约 **68%–76%**；扫描样区只做 **4%–6%** 平滑推近 / 平移，保持空间方向不变。
- 仅「路线生成 / 版本对照 / 成果提交」三次主要视觉演出允许较大镜头动作；学生操作过程中不自动抢夺镜头。

### 2.4 状态编码（非颜色依赖）
所有重要状态**同时使用颜色、形状、纹理和文字中的至少两种方式**。通用基线（可直接复用）：

| 状态 | 视觉表现 | 文字 / 形状补充 |
|---|---|---|
| 可走 | 自然地表 + 轻描边 | 圆点 + 「可走」 |
| 谨慎 | 琥珀斜纹 + 边缘一次呼吸 | 三角 + 原因短标签 |
| 不可走 | 深色交叉纹 + 封闭边界 | 叉形 + 触发规则 |
| 未扫描 | 自然地表 + 细节轻度压暗 | 空心扫描标记 |
| 不确定 | 噪点 + 断续轮廓 + 缺失块 | 问号 + 「不确定」 |
| 预测路线 | 半透明青色虚线 | 「预测」标签 |
| 版本路线 | 高亮实线 / 点划线 | 「v1 / v2」标签 |

风险层与路线层必须保持地形仍可辨认，不能用大面积纯色遮住证据。

### 2.5 性能底线（准入条件 #4）
- 集显 Windows 笔记本 1440×900 ≥60fps，iPad ≥45fps；像素比上限 **1.5**。
- 必须有**掉帧自动降级**后处理的分级开关（高清 / 均衡 / 流畅）。
- 最终联调阶段做 LOD、实例化、几何合并；但不得因此牺牲 §1 的美术语言。

### 2.6 资产清单（每个主资产记录）
用途、原始生成提示、尺寸、透明通道、可裁剪安全区、许可状态；视觉基准图（三视图 + 主美自审结论）随资产归档到 `docs/<任务名>/视觉基准图/`。

**来源**：`docs/火星任务/完整体验流程.md`（§4 任务舞台与视觉层级、§12）、`docs/火星任务/评审记录/3D资产主美术优化指南-2026-08-07.md`（§二–§八）、`AGENTS.md` 第二节准入条件 #4、第五节素材规则。

## 3. 游戏化任务体验流程设计规则

### 3.1 核心体验结论（不做什么）
- 这不是遥控游戏 / 积分游戏 / 看动画。沉浸感必须来自**连续的因果关系**：
  `我观察到证据 → 我改变一条规则 → 地图立即改变 → 对象产生可见后果 → 我能回到原因位置继续修改`。
- 核心快感是「这条路线 / 这个结果**是我的判断真实计算出来的**」。
- **禁止**：积分、星级、虚构解锁、预设成功剧情、长片头；禁止把「漂亮插画 + 下一步按钮」包装成项目学习。

### 3.2 六步短循环（PBL 闭环）
全课反复使用同一套可理解的行动语法（具体动词按任务替换）：
1. 扫描 / 观察一个真实对象。
2. 查看与该对象绑定的证据。
3. 改变一条规则或一项偏好。
4. 预测对象会怎样响应。
5. 运行真实算法 / 机制并观察后果。
6. 回到造成差异的位置修改。

每轮可增加新地形 / 目标 / 不确定信息，但**不重新发明一套操作方式**。

### 3.3 直接操作优先
- 操作发生在场景上，不在独立讲解页完成（扫描在地形上、规则变化直接重绘地图、结果解释通过点击差异节点）。
- **所有拖动操作都提供点击、加减按钮或方向键替代**，保证键盘与触控可达。

### 3.4 操作语言
主按钮使用**任务动作动词**，不使用笼统的「下一步」（如 `扫描前方`、`保存危险规则`、`生成路线`、`运行`、`回到差异点`、`对比两次运行`、`生成任务记录`）。

### 3.5 前 90 秒（留存第一关卡）
- 转场结束后场景**立即可操作**，不先播放讲解。
- 30 秒内可完成第一次有效操作；60 秒内至少一个对象因学生操作发生可见状态变化；90 秒内学生能看到自己的判断改变了对象前方 / 局部的可行方向。
- 第一次反馈不要求学生先读懂全部约束或公式。

### 3.6 单次任务内节奏
- 每 **60–90 秒**至少出现一次由学生操作触发的可见后果。
- 第一轮完整核心机制运行约在**第 8 分钟**前开始，不把核心回报拖到任务中段。
- 重要解释尽量贴在对象 / 路线旁，不把学生频繁带离主舞台。
- 预测、运行、定位原因、修改形成连续动作，不拆成多个问答页面。
- 全程**只有一个主要视觉焦点和一个当前主要操作**。

### 3.7 确定性（准入条件 #3）
- 同种子 + 同输入必须得到同结果；模拟使用固定时间步并与渲染帧率解耦。
- 禁止 `Math.random()`，所有随机走可注入的种子化 PRNG。
- 所有搜索波、路线、回放、版本对照必须来自当前配置的**真实算法输出**，不使用预录路线或预设成功动画。

### 3.8 KIBO 介入规则
- KIBO 不连续讲课，仅：新阶段一句话说明目标；约 45 秒无有效操作给第一级方向提示；连续两次相同问题时指出可检查的证据位置；对照完成时提问。
- 提示分三级：指出目标 / 指出可检查区域 / 演示一次操作（不给出最终阈值或权重组合）。
- 提示出现时**不冻结主舞台**；学生操作后提示立即收起，同一级提示不重复播放。

### 3.9 留存与回访设计
- 前 90 秒建立第一次因果反馈；第 8 分钟前进入第一轮完整机制运行；三段均由真实数据与算法驱动。
- 不靠强制失败制造紧张；若首轮已通过，后续轮次仍通过优化目标产生新的可见取舍。
- 完成结果在探索舱世界中持续存在（如保留路线痕迹、知识节点标记「已应用」），其他已发布任务直接可见、可直接开始，不设虚构解锁。

### 3.10 时长
- 单课目标时长 ≤30 分钟；所有任务都必须真实运行、可复现，并至少包含一次测试和修改。

**来源**：`docs/火星任务/完整体验流程.md`（§1 核心体验结论、§2 沉浸与留存、§3 核心交互模型、§6 完整流程总览、§10 KIBO 介入、§14 留存与验证）、`AGENTS.md` 第二节准入条件 #3、第九节体验质量标准。

## 4. UI 交互设计规则（通用 UI 一致性）

### 4.1 设计原则
1. **Viewport 优先**：3D 场景是主角，UI 只出现在边缘，且默认半透明 / 可收起。
2. **一次一个目标**：屏幕只显示「当前要做的事」，不堆叠多面板。
3. **空间化交互**：深度操作（规则设定、训练、选择）绑定到场景中的 POI / 操作台，而不是常驻面板。
4. **KIBO 即引导**：用 KIBO 对话气泡替代说明书和标题说明。
5. **开发工具完全隐身**：调试面板、性能数据、机位条默认不可见，仅通过快捷键或显式开关打开。

### 4.2 通用 UI 组件（跨任务必须一致）
以下组件在**所有任务中布局、语义、图标、交互一致**，不允许各任务另起皮肤：

| 组件 | 位置 | 内容 / 规则 |
|---|---|---|
| 目标追踪器 | 左上角（常驻） | 当前阶段名 + 一句话目标 + 进度点（6 步 PBL）；点击可展开任务日志 |
| KIBO 对话气泡 | 中上方（上下文触发） | 圆角气泡 + KIBO 小头像，≤2 行；约 3 秒淡出，按键可立即关闭 |
| 系统按钮 | 右上角（常驻极简） | 音效 / 画质（高清·均衡·流畅）/ 退出，全部图标按钮 + hover tooltip |
| 状态徽标 | 左下角（常驻） | 当前模式 / 能量或载荷等关键状态 |
| 小地图 | 右下角（可缩放） | 默认 96×96，点击放大 160×160；显示已探明 / 路线 / 对象 / 目标 |
| 操作提示栏 | 底部中央（短暂） | 仅在可能需要时显示（如「WASD 驾驶，E 交互」），5 秒无操作淡出 |

### 4.3 视觉风格
- 玻璃态面板：深色半透明背景 + 细边框 + 模糊 backdrop。
- 面板圆角 12px，按钮圆角 10px；清晰无衬线，中文优先系统字体。
- 主色保持暖橙沙地 + 冷青重音（各任务可在此骨架上定义自己的 palette，但不得改变组件形态与层级）。

### 4.4 触控与键盘（无障碍基线）
- 所有触控热区 **≥44×44 CSS px**（含滑杆、质量按钮、画质胶囊等易被忽略控件）。
- 画布 `tabIndex=0` + 方向键调方位 / 视距；阶段切换、规则、重规划、重置、声音、画质均为原生可聚焦控件；**键盘可走完全流程，无死胡同**。
- 焦点样式清晰，不被扫描纹理 / 路线光带覆盖。

### 4.5 非颜色编码
- 状态用「文字标题 + `tone` 类 / 图案 / 形状」多重表达；未探测区用斜向硬边影线（非纯色）；激活态用边框 + 文案（`aria-current` / `aria-pressed`），不只靠颜色；音效开关用图标 + 文案。
- 色觉障碍用户可凭图案 / 文字 / 形状区分状态。

### 4.6 减少动态效果（prefers-reduced-motion）
- 启用后关闭：推镜、视差、扫描扩散、对象残影、粒子、入场环绕、冲击震动、FOV 速度变化、天空飘动等**全部环境动效**。
- **保留可读静态画面**：对象基准位姿仍写入，学生看到的是「停住的等价画面」而非空白；所有状态、原因、代价信息完整保留。
- 系统级开关到各装饰层闭环，无需逐页配置。

### 4.7 动效系统
**响应层级时间表**（所有任务统一节奏）：

| 类型 | 目标时间 | 用途 |
|---|---:|---|
| 按下 / 选中 / 拖动响应 | 0–100ms | 证明操作已被接收 |
| 地块 / 数值 / 局部方向更新 | 100–300ms | 建立变量与结果的连接 |
| 镜头定位 / 面板切换 | 180–500ms | 解释空间与状态变化 |
| 路线收束 / 结果聚焦 | 600–1500ms | 强调关键计算结果 |
| 任务转场 | 约 1200ms | 维持探索舱到任务的空间连续性 |

- 算法计算超过 300ms 时，必须先显示真实计算已开始，不能让主按钮无反馈。
- 动效优先级：当前操作 > 受影响对象 > 执行结果 > KIBO 提示 > 环境待机；环境动效不得盖过前四项；页面同一时间**只能有一个高对比运动焦点**。
- 任何与学习无关且持续超过 5 秒的运动必须可暂停或不播放。

### 4.8 声音规则
- 声音**默认关闭**，必须由学生主动开启；首次进入任务不得自动播放。
- 声音不承担唯一信息，所有反馈都有视觉与文字等价形式。
- 不制造操作奖励循环（不为每个格点重复播放声音、不用「胜利声 / 失败声」暗示唯一正确策略）。
- 连续拖动期间只在开始与松手确认时播放；KIBO 语音如制作须提供同步字幕与独立关闭；音量 / 静音状态存当前浏览器。

### 4.9 降级诚实（准入条件 #6）
- WebGL 不可用 / 着色器编译失败 / 连续 5 秒低于 25fps 时，3D 舞台自动降低画质（分辨率 / 像素比 / 后处理分级），确实无法继续时显示**人话说明的提示页**。
- 提示必须诚实：说明「任务内容完全一致，可继续使用核心功能」，**不得谎称已切换到其它版本**。
- 降级时卸载 3D 舞台（停 RAF、释放几何 / 材质 / renderer），防止后台空转。
- 不崩溃、不谎称切换版本。

## 5. 验收与 QA（三方评审）

每个任务发布前必须同时通过**视觉评审**与**教学评审**；两者冲突时教学优先。

### 5.1 缺陷清单闭环
- 主策划（设计）、主美术（视觉）、主程序（工程）各出一轮书面缺陷清单。
- 逐条处置后复审，直到任一轮提不出具体缺陷为止。

### 5.2 截图工装
- 用 Playwright 无头截图工装从多个机位捕获**真实帧**；所有视觉结论以截帧为准，不以「代码应该会这样渲染」为准。
- 每个主资产截正 / 侧 / 斜 45° 三张，与三视图并列对比，主美术逐条勾选验收项。

### 5.3 确定性回归
- 同种子同输入连续两次运行，模拟输出逐项一致（路线、代价、访问节点、无路径处理）。

### 5.4 降级演练
- 强制关闭 WebGL 与强制低帧两种情况，验证：诚实提示页、3D 舞台不崩溃、画质分级自动生效、降级后停 3D 防空转。

### 5.5 无障碍专项
- 44px 热区全覆盖、键盘完整流程、reduced-motion 等价、WCAG AA 对比度、非颜色编码。

### 5.6 通用验证清单
- `AGENTS.md` 第八节 1–6（类型检查 / 生产构建 / 三视口浏览器 / 键盘·减少动态·高对比 / 转场走查 / 截图复核 / 可见图与控件）。
- 3D 任务额外 7–10（截图工装多机位 / 双评审闭环 / 确定性回归 / 降级演练）。

**来源**：`AGENTS.md` 第八节验证与交付、`docs/火星任务/评审记录/M9-无障碍与降级-QA-2026-08-07.md`（§四 已执行修复清单）。

## 7. 反模式清单（火星任务迭代教训，务必规避）

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 把「开发者检视页」当产品页（调试面板 / 性能数据 / 机位条常驻） | 学生 10 秒说不清要做什么 | 开发工具默认隐身，仅显式开关打开（§4.1.5） |
| 2.5D 与 3D 双版本并存，降级谎称「已切平面版本」 | 误导性无障碍信息 | 不保留 2.5D；降级诚实说明内容一致（§4.9） |
| 美术细节偏少（光滑球、贴条代替块面） | 剪影不可读、不像目标物 | 三视图基准 + 大面分块 + 面板线（§1.5/§1.6） |
| reduced-motion 只冻结对象动画、漏掉天空飘动 | 前庭敏感用户仍被晃动 | 系统级开关贯通所有装饰层（§4.6） |
| 触控热区 38px（质量按钮等） | 违反 WCAG 2.5.5 | 所有控件 ≥44×44（§4.4） |
| 状态只靠颜色区分 | 色觉障碍用户丢失信息 | 颜色 + 形状 / 纹理 / 文字（§4.5、§2.4） |
| 缺三方 QA 或只过一轮 | 真实缺陷漏到发布 | 主策划 / 主美术 / 主程序各出清单，闭环复审（§5.1） |
| 用预录路线 / 预设成功动画冒充真实算法 | 违反内容真实性，误导学习 | 所有反馈来自真实算法输出（§3.7） |
